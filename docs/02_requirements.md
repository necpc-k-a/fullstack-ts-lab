# 要件定義書（Requirements Specification）

本ドキュメントは、本アプリケーションが提供する機能要件および非機能要件について定義します。

---

## 1. システムの目的

TypeScriptおよびReact、Express、PostgreSQLを活用し、完全な型安全性を備えたCRUD（作成・読み取り・更新・削除）操作が可能なユーザー管理システムを提供する。

---

## 2. 機能要件

### 2.1 ユーザー管理機能 (CRUD)

| ID | 機能名 | 詳細仕様 |
| :--- | :--- | :--- |
| **F-01** | **ユーザー一覧表示** | 登録されているすべてのユーザー（ID、名前、メールアドレス）を一覧でカード形式表示する。データはID昇順で整列する。 |
| **F-02** | **ユーザー追加** | ユーザー名およびメールアドレスを入力して新規登録する。登録成功時には一覧を自動更新する。 |
| **F-03** | **ユーザーインライン編集** | 一覧上の「編集」ボタンを押下することで、該当行をインライン入力フィールドに変更し、名前・メールアドレスの更新を可能とする。 |
| **F-04** | **ユーザー削除** | 一覧上の「削除」ボタンを押下することで、該当のユーザー情報をデータベースから物理削除する。 |

### 2.2 ユーザーインターフェース・フィードバック機能

| ID | 機能名 | 詳細仕様 |
| :--- | :--- | :--- |
| **F-05** | **トースト通知 (成功)** | ユーザーの追加・更新・削除処理が成功した際、画面中央上部に成功メッセージ（暗色背景）を自動表示する（3秒後に自動消滅、または手動閉じ可能）。 |
| **F-06** | **トースト通知 (エラー)** | 通信エラーやDBエラーが発生した際、画面中央上部にエラーメッセージ（赤色背景、警告アイコン付き）を表示する。 |
| **F-07** | **件数バッジ表示** | ユーザー一覧のヘッダー部分に、現在登録されているユーザーの総件数をリアルタイム表示する。 |

---

## 3. 非機能要件

### 3.1 画面・UX・レスポンシブ要件
* **レスポンシブデザイン**: スマートフォン（1カラム）からPC（多カラム・広幅表示）まで最適化されたTailwind CSSレイアウトを提供する。
* **リアルタイムバリデーション**: フロントエンド側で空文字送信の制御や入力チェックを行い、無駄なAPIリクエストを防止する。

### 3.2 保守性・開発運用要件
* **型安全性の担保**: `shared/types.ts` によるフロント・バックエンド間でのDTO (`CreateUserDto`, `UpdateUserDto`) の完全共有。
* **コンテナ化**: Docker Compose を用いて、環境依存のないワンコマンドでの起動環境を提供する。
