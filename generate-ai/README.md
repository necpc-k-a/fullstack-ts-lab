# generate-ai (Gemini / AI 連携用フォルダ)

本フォルダは、生成AI（Gemini カスタムGem 等）へプロジェクトの全体仕様・最新コードを共有するためのツールおよびドキュメントを集約・管理するディレクトリです。

---

## 1. フォルダの存在理由・目的

* **前提知識の一元共有**: 生成AIに本プロジェクトの全構造（設計書・共通型定義・実装コード）を1つのファイルとして読み込ませることで、回答精度を最大化します。
* **ワンクリック更新**: ソースコードや設計書を変更した際、手動でコピー＆ペーストすることなく、バッチファイル1発で最新状態の統合テキストを出力・更新できるようにします。

---

## 2. 含まれるファイルと役割

| ファイル名 | 役割・概要 |
| :--- | :--- |
| **`README.md`** | 本フォルダの目的、バッチファイルの処理内容、運用手順を解説するドキュメント |
| **`build-context.bat`** | プロジェクト内の設計書・コードを取得し、`PROJECT_ALL_IN_ONE.md` へ自動結合するスクリプト |
| **`PROJECT_ALL_IN_ONE.md`** | バッチ処理によって生成される、Gem（AI）の知識（Knowledge）アップロード専用ファイル |

---

## 3. バッチファイル (`build-context.bat`) の処理内容

1. **実行位置の自動補正**: バッチファイルをどこから実行しても正しく参照できるよう、プロジェクトのルートディレクトリにカレントディレクトリを移動します。
2. **文字コード設定**: 日本語や特殊文字の文字化けを防ぐため、一時的に文字コードを `UTF-8 (65001)` に変更します。
3. **統合ファイルの初期化**: `PROJECT_ALL_IN_ONE.md` を新規作成（すでに存在する場合は上書き）します。
4. **順番指定によるファイル連結**:
   * `README.md`（プロジェクト全体の概要）
   * `docs/` 配下の全設計書（システム構成、要件定義、画面仕様、API仕様、DB設計）
   * `shared/types.ts`（共通型定義）
   * `backend/` および `frontend/` の主要ソースコード・スキーマ定義
   * `docker-compose.yml`（インフラ構成）
5. **コードブロック構文による構造化**:
   * 各ファイルの開始位置を示すファイルパス見出し（`# File: ...`）を挿入します。
   * **自動判定処理**: 拡張子が `.md` 以外のファイル（`.ts`, `.tsx`, `.prisma`, `.yml` 等）については、拡張子に応じた言語名を指定したコードブロック（```` ```typescript ```` 等）で自動で囲い、AIの解析率向上を図ります。

---

## 4. 運用・利用手順

1. **バッチの実行**:
   `generate-ai/build-context.bat` をダブルクリックします。
2. **生成結果の確認**:
   同フォルダ内に `PROJECT_ALL_IN_ONE.md` が生成されていることを確認します。
3. **Gemへのアップロード**:
   Gemの編集画面を開き、「知識（Knowledge）」に生成された `PROJECT_ALL_IN_ONE.md` をドラッグ＆ドロップして保存します。
